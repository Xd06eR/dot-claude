## 1. Identity + working style

Bar: durable facts about the user and the collaboration that no live harness file already carries; verbatim quotes only where the wording itself carries the rule.

- **Full-stack AI engineer** (frontend + backend + LLM/AI integration + infra): designs specs, reviews every line, never writes code by hand; pitch at the design/trade-off level, not the implementation level.
- **Two-layer review:** the agent is the first reviewer and reviews everything comprehensively itself; the user is the final review, a backstop, not coverage — "Although I do the review manually, but I would miss something as I am human. So, you should still review them all regardlessly in detail and comprehensively."
- **Agent drives, user steers:** "all should be done by you (the agent), I am only the user who give you ideas and ask you."
- **Restructure appetite:** when a section reads messy, the user chooses deeper restructure over light cleanup — "Yes, probably light cleanup, but I actually want you to restructure this workflow into more effective and better performance format and structure."
- **Git labor split, agent side:** everything git-adjacent beyond the user-run mutations is the agent's work — "I only review and you do the work for me." No attribution lines on commits. Never revert the user's hand edits via git checkout.
- **GitHub = human review gate:** "I actually don't do automated GitHub work by AI directly, I usually review what you generated before doing in GitHub... in GitHub, it is much more strict on the standard."
- **Student, multi-domain; CLAUDE.md stays universal:** "As I am a student, I do many things, mostly AI work... I don't want the CLAUDE.md to be too limited to a specific structure of work, they should be high level instructions." Per-type layering lives in project CLAUDE.md and project rules.
- **OSS artifact publication:** design/plan/ADR docs push to the same GitHub repo, open and closed source alike; push counts as publishing, checked inside the existing review pass. Per-document exceptions only: commercial strategy, operational security detail, PII/secrets, legal.
- **Reject-on-comment:** a tool call the user rejects with a comment is a silent rejection — track landed versus rejected, and re-apply only after addressing the comment ("I think I rejected the edit due to the comment, as Claude Code reject tools when commenting."). A review question "why explicitly mention X" is a cut request, not a request for justification.
- **Serial per-edit landing:** explain one edit, fire one Edit, and the user's veto arrives as a comment in the tool prompt; parallel batches of durable edits never fire. The harness-maintenance per-edit gate carries the tool mechanics.

## 2. Environment + loading model

Bar: machine- and account-level facts a session cannot infer and cannot change (provider setup, injection and loading mechanics, measured costs, environment failure modes).

- **settings.json waiver:** never flag the file, the `ENABLE_TOOL_SEARCH` value, or token placement (a per-provider toggle the user manages); only genuinely new settings may be proposed. Never commit settings.json with a token present; commit settings alone at token-free moments. settings.local.json is gitignored and is the safe token home; the repo is public, so a staged settings.json token is a public leak.
- **Windows gh config holds no secret:** the gh token lives in Windows Credential Manager and hosts.yml carries no secret, so the gh-config read deny is belt-and-braces, not a live threat surface.
- **Environment facts (govern cost/spend proposals):** the user holds the API key; the agent cannot pay, enroll services, or access cloud accounts — "I don't like linking AI to any platform which you will not have the access either."
- **Memory layer off:** autoMemoryEnabled is false and no global MEMORY.md sidecar exists — rules and CLAUDE.md load in every project, strictly better than a sidecar; lessons enter through CLAUDE.md's Lesson capture (proposal-gated).
- **Harness scope: Claude Code only:** the harness is maintained for Claude Code alone; portability to other agent CLIs is never a factor in component or rules decisions.
- **Scoped-rule loading mechanics:** `paths:` frontmatter loads a rule on matching file reads (Read/Edit), never at session start; writing a new matching file does not trigger the load, so the working rule is read code before writing it. Scoping exists so non-coding sessions never pay for coding checklists; the insurance model is accept-and-watch — no trunk pointer line, and only a real missed-rules incident reopens it. Harness rules themselves sit in the harness's project-rules dir and load only when the cwd is the harness.
- **Skill paths: frontmatter is supported and unused:** skills accept the same paths: scoping that rules files use, and zero skills in the inventory carry it; whether a paths:-scoped skill's description still injects on non-matching sessions is UNVERIFIED (probe pending in Open items).
- **Description-injection cost has two rulers:** the full-listing basis and the description-value basis measure the same corpus differently, so a description-cost figure is meaningless until it names its basis.
- **User-invoked skills inject no description:** a component with disable-model-invocation stays out of the always-on listing entirely; its discoverability is the user typing the name, never context, so trunk text proposing one at "its moment" misreads the mechanism.
- **Subagent contexts receive the same rules injection as main:** unscoped rules are present at a subagent's start and paths-scoped rules inject on its matching reads; a dispatched subagent can itself invoke the Skill tool (probe-verified).
- **Built-in feature-disable layer:** settings.json carries the feature flags (disableWorkflows, disableArtifact, disableRemoteControl, disableClaudeAiConnectors, disableSkillShellExecution, disableBundledSkills) — bundled skills stay fully disabled; /doctor stays (user-typable diagnostics, model-hidden); a same-name project skill replaces a bundled one in the injection; bundled claude-api stays dead while the configured provider cannot serve it (re-evaluate on provider change). Permission denies block calls only — they never remove tools from the injected context, so deny lists save no tokens.
- **Security-plugin layer:** the injected at-write-time pattern warnings are the harness's only deterministic write-time net and stay on; the plugin's two LLM review layers stay off — the Stop-hook diff review hijacks the turn boundary on findings, and commit-time review is permanently dead here because the user runs every commit (if commit-time security review is ever wanted, the route is the Review phase's security-auditor under the user's gate, never the plugin's layers). The shared master switch for the two LLM layers is ENABLE_CODE_SECURITY_REVIEW in settings env; the un-gated per-prompt baseline capture (subprocess latency, zero tokens) is the accepted residual cost of keeping the pattern layer.
- **Output-cap mechanics:** unrecognized gateway model IDs default to a 32000-token output cap and thinking counts against it, so a long analysis turn dies before its first Write; the raise is CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000 in settings env (going higher rejected: the excess clamps to the provider ceiling and deepens the silent-generation window). Subagent cap deaths have no auto-resume on any version, and a resumed agent that emits nothing after the message lands does not recover — interrupt and dispatch fresh.
- **Task-tool denies are dead config:** the TaskCreate/TaskGet/TaskList/TaskUpdate denies in settings.json predate the tools' rename and match no live tool; the startup warnings on unregistered configs are the accepted price.
- **Denied-by-name system tools:** PushNotification, RemoteTrigger, AskUserQuestion, EnterPlanMode, and ExitPlanMode are denied in settings; plan mode is doctrinally off twice over (it delegates exploration to a subagent, conflicting with the contents-vs-answer dispatch test, and the grill skills own the interrogation moment).
- **CC-switch rewrites settings.json wholesale on profile switch:** hand-edit settings.json only after the session's final switch, or the edit is overwritten.
- **Permission-edit posture:** a permission change that sends anything out — including query text through an allowed lookup — is flagged to the user before it lands, and every proposed entry is grounded in a doc the user can read first, never asserted from memory ("why? point that docs to me.").
- **Session mechanics:** compaction is not a new session (same session ID; the summary continues it), SendMessage resume works across compaction (fallback: rebuild the brief from written probe outputs), and an agent stopped by the user is not agent-side resumable.
- **Stacked scoped loading and the delta principle:** reading a matching file injects the whole stack at once (common plus every matching language layer), so cross-layer dedup pays multiples of single-file trims; a language layer earns entries only for what common rules and strong-model priors cannot already cover.
- **Token-defense taxonomy:** standing-context defenses class as [P] probe-proven, [V] version pins, [N] numbers, [C] protected checklists, [M] framework mechanics, [L] anchors, [R] routing, [U] presumed-only; the bulk of a rules layer is enforcement surface — a firing-guarantee decision, not an inferability question — and the class, never the token count, decides whether a defense holds.
- **Trunk-as-frontier:** the trunk (CLAUDE.md) is a larger always-loaded surface than the entire common rules layer, so standing-context reduction starts there, not in the rules tree; the comparison re-derives whenever either side changes.

## 3. Working principles

Bar: named methods and stances governing how harness work is judged, each with its why; nothing a SOTA model infers unprompted.

- **Work-sequence principle "3M":** Make it work / Make it right / Make it fast — the user's own sequencing lineage, kin to the Rule of Three ("So the Rule of Three is similar to my previous principle of 3M?").
- **Firing guarantees over conditional token savings:** a standing rule's reliable firing outweighs relocating it out of always-loaded context — "the reason that I don't put them into skill is that I afraid of forgetting to use them."
- **Context dilution and re-trim:** bloated context dilutes attention; an 80%+ system-prompt cut showed no eval drop ("We should trim our context for more intelligent models"). Verification and self-correction belong in the architecture, not the prompt. Re-trim standing context per model release — each release widens what the model infers unprompted; the user's judgment is the gatekeeper meta-layer.
- **Admission test for standing context:** always-loaded material is for what is true for every prompt — context is a standing cost paid on every request, guilty until proven useful. Delete in blocks, not lines: sentence-level cuts sit inside eval noise. Failure taxonomy (Breunig): poisoning / distraction / confusion / clash, clash being the self-authored contradiction class. Rules land as judgment ("X is usually right here because <reason>"), never bare.
- **Unknowns bottleneck:** work quality is bottlenecked by clarifying unknowns, not model capability — blind-spot pass, throwaway prototypes, one-question-at-a-time interviews, code references over screenshots, implementation-notes log, pre-merge quiz.
- **Ralph-wiggum-loop:** early completion plus a soft gate ships half-done work; the fix is an objective gate — "not a verifier that has an opinion".
- **Comprehension-debt:** output outpaces understanding; review scale must track automation scale — "gates rot".
- **Deep over shallow (深模組/淺模組):** AI leans shallow — easy to build, hard to manage, lost on large projects; prefer deep modules (narrow interface, rich implementation). 規格化/流程化/模組化 — spec-ify, process-ify, modularize — are what make AI vibe coding more than a toy.
- **Multi-agent decomposition and verification:** decompose by context boundary, never by role (role splits spend more on coordination than work); multi-agent remedies exactly three constraints — context protection, parallelization, specialization past ~20 tools — at a typical 3-10x token cost. Pool independent judgments, never debate: debate induces premature consensus, and centralized verification cuts error amplification (17.2x → 4.4x). Unfiltered review runs 12-15% precision; the verify-to-disprove stage is what reaches <1% — never ask "what's missing" freeform, LLM judges are weakest at exactly that (FineSurE's said-but-not-written alignment is the published method). Production pattern: parallel specialized finders → disproof verifier → severity ranking → the human keeps the verdict. Mechanical gates — proof-of-concept execution, non-zero exit — are what make parallel fan-out trustworthy; a graph view exists because parallel work is otherwise unobservable. The verification pass's named failure is early victory; the fix is an explicit complete-suite demand.
- **Anchor edits insert, never replace:** the anchor text stays verbatim in both old_string and new_string; new content goes beside it, never over it ("Why are you keep removing unrelated part when you edit?" — three corrections).
- **Plan-acceptance gate:** before asking the user to accept a plan, state the method — what was dispatched, what was read, which layers are covered — and expect a fact-check demand next.
- **Doc-sync standing instruction:** durable docs carry the latest and most accurate context, no ambiguity ("All docs should be containing the latest and most accurate context. Try your best to avoid any ambiguity and unclear context."); sweep for staleness before every compact.
- **Imperative verbs stay:** instruction bullets keep their imperative verbs — stripping them softens the rule ("Just asking, why remove the verb?").
- **Justify-before-execute:** on a heavy plan, justify per item that it is worth doing before executing anything.
- **Standard over house:** reason from the standard or best practice, neither from the user's CLAUDE.md preferences nor by citing a named standard ("Don't lean to my CLAUDE.md preference... You should reason about how would the docs format." / "use the standard/best practice in formatting.").
- **Gate status is the user's word:** never mark a gate, batch, or review done without the user's explicit confirmation; status lines stay "in user review" until then; the agent's expectation of completion is not completion. A full review runs as the user's own acceptance pass: they name the files and the order, the agent evaluates and proposes only, and the review is never declared finished ("Never declare my review finished.")
- **Inference-bar re-test:** every always-loaded instruction is re-tested against the inference bar (a SOTA model does it unprompted, even under time pressure) whenever standing context is restructured; relocation fixes home-correctness, never permanence, and what survives lives exactly once.
- **Two-layer resolution for rules/skill overlap:** resolve by layer, never by deletion — rules keep the policy and the attention checklists that must fire on edit; skills own the depth invoked on demand. A rules-file reference to skills names the complete relevant family, never a partial set.
- **Three-way restructure method:** for a contested rewrite, draft in parallel (main context + fresh subagent), apply the mechanically identical overlap first (script-verified), then walk every divergence one-by-one for user verdicts — the divergence review is where the value lands.
- **Live-test protocol:** when a reworked surface goes into real-session use, commit mid-arc and let the user's hand edits land on top; the next session reads the diff, judges every change against the harness principles, and reverts only the bad ones with reasons — the user's reasons win conflicts.
- **No agent time estimates:** wall-clock inputs are invisible to the agent (review speed, permission prompts, machine latency, subagent runtimes), so any time estimate is a fabricated number; false precision harms planning more than no estimate.
- **Restoring a deleted rule needs live evidence:** an observation that the problem no longer occurs is contaminated evidence while the rule is still active during the window; the valid grounds are severity, form (a pure negative constraint is the weakest), and whether a safety net exists.
- **CP principle (fresh-context economics):** each fresh context costs a full artifact read plus its own reasoning, and the marginal-return curve is steep — the first fresh reader is the no-self-acceptance core and irreplaceable; a second to fourth pays only when the briefs are structurally different (same-brief contexts converge instead of corroborating); more almost never pays; minor work never warrants a crowd. Generation moments are the exception and keep their fan-outs — divergence is the product there, and a fresh-context pass must not trim them as violations. Review in the orchestrating main context is legal where a subagent built: no-self-acceptance bars the producing context, and the main context is a second one.
- **Fan-out audit reconciles in fresh context, then main:** parallel lanes report, a fresh-context reconciler adjudicates the conflicts, and the main agent reconciles the reconciler with first-hand corrections; the lane briefs are structurally different by design (the CP principle's condition for a second fresh context), and lane reports are pruned once their verdicts land.
- **The whole-surface audit runs heterogeneous lanes and lands serially:** parallel findings-only subagents (one lens each, surface split by file class or component, budget declared up front) report to main, which dedupes and falsifies the findings and lands the survivors one at a time; a fresh-context verifier confirms the landed bytes per dispatch-protocol's Batch final-audit.
- **Model-judged scores are named labels, never numbers:** adjacent numeric scores carry no real distinction and vary with per-model bias, so model-judged ratings report named labels; config values, measurements, and citations stay numeric.
- **Falsify-first came from missing counter-pressure:** main-context judgment questions meet no counter-agreement pressure, so the stance was coined as the active adversary — the rule lives in the trunk's Push-back; the durable half is that main-context judgment needs an adversary, not a longer prompt.
- **Superset lenses and verdict contracts:** two review lenses seated on one checklist produce correlated agreement that reads as confirmation — every lens owns a distinct checklist; and a verdict contract carries an explicit not-applicable value, because a scope-guarded reviewer otherwise improvises a silent pass. A lens earns its own file only when a generic reviewer plus one line could not produce it (the justification test).
- **Table edits byte-diff the whole structure:** deleting or editing a table column means diffing header, separator, and rows alike — the separator row is the silently missed one.
- **Prefer mechanical checks for earned rules:** a pitfall's durable fix prefers a mechanical check (hook, lint, CI) over a prose rule — the check fires where prose relies on attention.
- **Adversarial review is briefed finding-only:** the bulk-audit pass runs map → main-context audit → adversarial fresh-subagent review → apply → summary, and the adversarial reviewer is briefed with file:line + finding only, never the auditor's reasoning — a brief that carries the reasoning anchors the reviewer in the auditor's frame and turns the pass into confirmation of it.
- **Audit flags are diagnosis, not verdict:** findings from a review or audit pass are leads to verify, never instructions to execute; a buried gotcha can be load-bearing, so triage findings by evidence, never by prominence. The verification step lives in dispatch-protocol's No self-verification.
- **Content-preservation scan on consolidation edits:** scan the deletion side of the diff (`git diff | grep '^-[^-]'`) for lost backticks and acronyms, and keep the per-file word-count delta non-negative — losses hide in deletions, invisible to a read of the result; byte-diffing every code block and table cell lives in the dispatch protocol's merge criteria.
- **Rename-parks are live until the user rules:** a `.bak`-style rename parks a file, it is not a deletion signal — never clean up parked files without the user's word ("Don't delete it, I only renamed this, it is not a backup.").
- **Unclear instructions are a root cause, not an excuse:** "even though there are instructions, but you (the agent) still sometimes make the mistakes. It may due to the instructions are unclear" — when a standing instruction fails repeatedly, trade its breadth for unambiguity; contradictory guidance is an invisible tax (clash).
- **Merged bullets are element-checked against their originals:** a merge is complete only when every element of both source bullets survives it, and the check runs against the originals on the diff, never as a read of the merged result.
- **Preference, reasoning, mechanical routing for judgment calls:** mechanical questions verify in place; reasoning-from-wants questions escalate with a recommendation; pure preference goes to the user, never to a fresh agent ("as long as it is coding work... there is criterion, which is the wants").
- **Universality two-filter test:** an exception owned by a mode-skill (prototype skipping a production-weighted rule) does not count against a rule's universality, and conditional-within-default-mode content moves to the skill's home; the filter runs per work mode (production vs side-project/prototype), never by exception count.
- **Phase-anchored routing pattern:** a skill owning a mid-flow moment routes by a phase-anchored trunk mention plus its description (tdd: named at the trunk's build step, triggered by its description), never by wiring invocations into upstream skills; routing is verified at the phase moment itself (the skill is never step one), and never judged from a probe run with --tools "" — that flag strips Skill-tool planning, an environment flaw, not a routing failure.
- **Design-time guidance has exactly two homes:** skills or the trunk; paths:-scoped rules can never serve design time because design moments have no matching working file (grilling has no cwd).
- **Relocation math:** moving always-loaded words into a new skill's description saves nothing — the description is itself always-loaded and a thin skill is only a routing shell; relocation pays only when the receiving component already exists, and a rule the baseline probe shows firing (banned patterns hit at code-time) compresses in place instead of moving.
- **Indirect probes beat direct questioning:** to test whether a rule fires, seed a task simulation with non-canonical vocabulary and watch the behavior; asking "did rule X apply?" invites confabulated agreement.
- **Behavior-affecting trims get before/after probes:** a trim whose loss could change task behavior is verified by running the same task headlessly before and after it, never judged from the diff alone — a static read cannot see a firing rule go silent.
- **Baseline-probe method:** a no-file-read probe is a natural no-rules baseline; unprompted-produced means inferable means deletable, missed means teeth means keep — "settle it by running the document, not by debate". Probe silence never proves capability (pins stay). Mechanism-class hits transfer across SOTA models while taste-class results vary within one, so a defense names its class; under the always-loaded confound (prior vs trunk coverage both zeroing a rules file's marginal value) a defense must say which. Probe reading is item-precise, generation moment and review moment are distinct, probe questions and outputs transfer to subagents verbatim, and adversarial re-checks open a NEW context (resuming the trim auditor to defend grades its own work). The structure is trim auditor × fresh defender × probes, with a pre-commit dual-resume carrying the rejected-class checklist.
- **Globs declare the need-moment:** a scoped rule's glob states when the rule is needed, derived from the actual use case; token savings are a by-product, never the motive ("I don't want you to change the glob based on token usage. I want you to based on the actual use case, the glob should represent when do it needed").
- **Landmark principle:** a heading that is an audit's only scan landmark for a skill route, mechanism string, or named convention may not be demoted even when its text survives in the body; a cross-file merge is a glob-scope change, not a structure change.
- **Trim accounting reports against the promise:** a promised savings range is a commitment — delivered deltas are reported against it with misses on record, never silently re-baselined ("省不到 token is a lie, reducing 30 tokens is reducing...").
- **Preference-carrying context beats fresh subagents on trim proposals:** the session holding the user's demonstrated preferences finds more trimmable material than a fresh reader ("you are finding more trimmable section than your subagents... as you know my preference"); freshness serves verification and defense, never preference work.
- **Keep/drop judges purpose and workflow fit, never invocation count or provenance:** usage frequency is supporting evidence, never the criterion — a highest-measured-cost component stays when the purpose is real, and provenance never enters the call.
- **Workflow-skill anchor threshold:** a trunk or rules anchor is earned only when the skill's moment is a mid-phase instant the model will not think to invoke on its own ("phase 內部時刻，模型自己不會想到要 invoke"); phase-explicit spine steps self-defend through their pipeline position (tdd anchors for most builds, code-review sometimes).

## 4. Component standards

Bar: decisions and whys for authoring and curating skills, commands, agents, rules; live rule text lives in harness-maintenance and rules, pointed at, never copied.

- **Generic args, never hardcoded names:** commands and templates take generic argument names — never hardcode a project's folder or file names ("Don't specifically call 'system_design/' or something else... I may use other").
- **Universal principles migrate to the trunk; rules keep mechanics:** a principle in a rules file that applies to every prompt moves to CLAUDE.md; the rules file keeps the mechanics and the checklists that fire on its scoped reads.
- **The 200-line bar calibrates, never caps:** instruction files target under 200 lines (Anthropic's recommendation) as a membership test, not a numeric cap: procedures belong to rules and skills, every-session facts to the trunk; a project instruction file earns entries by purpose and gotchas, never content learnable by listing directories.
- **External corpora are content donors, never authorities:** clone-and-mine a source for adoptable content on merit; never reconcile the harness tree against the source's state — its goals are not this harness's, and authority status imports its drift.
- **Coding and language-specific detail lives in scoped rules, never the trunk:** CLAUDE.md stays at principles, preferences, and instructions; per-language toolchains, style, verification pipelines, and naming detail default to the language's rules file, where scoped loading puts them in view exactly when that language is edited. No pointer from the trunk to a scoped rule either — scoped loading is the discovery mechanism, and a trunk pointer recreates the always-loaded cost scoping exists to avoid.
- **The trunk never points at harness-internal files:** CLAUDE.md ships alone and loads where the harness's files do not exist, so a pointer from it dangles by design; what it must convey stays self-contained in its own text.
- **Transparency principle:** a component with no readable body (a hidden built-in) may never be referenced from a durable file — the reader cannot verify what the reference promises, and the reference rots invisibly with the component.
- **Routing lives in descriptions; only conversational openings are fixed:** a phase-membership table in always-loaded context is removed form — it pays for what the injected descriptions already carry, and an overflowing phase is a curation signal, not a layout problem.
- **A cede clause is scoped from bodies, not descriptions:** the clause must name the slice the sibling's body actually owns, and the ceder's own body keeps what it can really do; a description-level read (frontmatter evidence alone) both over-cedes and hides in-house capability.
- **House skill style (mattpocock lineage):** terse, accurate terms, free phase transitions; one skill = one specific purpose; other sources complement, never set the bar. Drops are usage-based only and never silent — every drop records its reason.
- **Skills take natural-language invocation:** a skill is an SOP for a task, never a parameter parser — "YOU DON'T SKILL IS JUST THE SOP FOR A TASK" — so a body never enumerates input combinations and placeholder-argument parsing is banned outright.
- **Fixedness is proportional to mechanical consumption:** fixed skeleton headings exist only for machine-carried blocks (checklist syntax, contract tables); everything a human reads stays free-format.
- **Every agent-consumed artifact gets a named format spec:** one spec per artifact family (CONTEXT-FORMAT, ADR-FORMAT), lazily created, with a thin pointer from its entry point; the artifact's format lives in the spec.
- **Every-run content stays inline; pointers only for branch-skipped blocks:** a cross-skill file read at runtime costs more than a small copy, so content every run of a skill needs stays inline; only blocks some branches skip sit behind a pointer.
- **Aspects and lenses are the user's control surface:** review-family skills name their aspects or lenses at invocation — the naming is the trim lever, symmetric with description routing.
- **Locality: no caller-specific exceptions in general-purpose skills:** a skill serving many callers never carries one caller's exception; the invoking skill owns its own steps' staffing.
- **Format calibration for durable text:** blank line between distinct ideas, combining too-short clauses into one block, blank line before and after every list, periods over semicolons for short clauses, sub-bullet indent = parent marker width + 1. Stick-together (a multi-claim block without blank-line separation) is the primary defect — a single atomic sentence is exempt even when long; hard-wrap (manual screen-wrap mid-sentence) is always a defect. Bold-lead-in principle bullets are a false-positive class — never split them.
- **Size flags calibrate judgment, never cap:** components carry no numeric size caps — shape bars govern; a length flag triggers review, never a reflexive split, and a flat in-skill reference is a fine arrangement (motion-ui at 749 lines was judged not sprawl).
- **Rules are agent-facing, never user-facing:** rules files carry the agent's attention-directing material only — keybindings, environment setup, and permission advice belong to user-facing docs, not rules.
- **Owned components are tailored descendants, not copies:** every ported component deliberately differs from its source — format standardization, retargeted references, house extras; a drift comparison hunts content deltas only, because style deltas are the tailoring itself, never a defect; no blind re-syncing.
- **Procedure folds into the skill; rules keep the route:** procedure content with a skill home moves into the skill body, and the rules file keeps the routing line plus the invocation form (call the Skill tool with "X"); stances shaping continuous behavior stay full-text in rules.

## 5. Workflow decisions

Bar: rulings that shaped the artifact and workflow system with their why; mechanics live in the workflow skills.

- **Claude Code permission mechanics (docs + live verified):** deny > ask > allow, first match regardless of specificity — a catch-all ask defeats every specific allow (the rtk proxy catch-all was removed for exactly this; defaultMode=default with bypass disabled makes unlisted commands prompt anyway).
