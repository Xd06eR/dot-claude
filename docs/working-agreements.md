## 1. Identity + working style

Bar: durable facts about the user and the collaboration that no live harness file already carries; verbatim quotes only where the wording itself carries the rule.

- **Full-stack AI engineer** (frontend + backend + LLM/AI integration + infra): designs specs, reviews every line, never writes code by hand; pitch at the design/trade-off level, not the implementation level.
- **Two-layer review:** the agent is the first reviewer and reviews everything comprehensively itself; the user is the final review, a backstop, not coverage — "Although I do the review manually, but I would miss something as I am human. So, you should still review them all regardlessly in detail and comprehensively."
- **Agent drives, user steers:** "all should be done by you (the agent), I am only the user who give you ideas and ask you."
- **Restructure appetite:** when a section reads messy, the user chooses deeper restructure over light cleanup — "Yes, probably light cleanup, but I actually want you to restructure this workflow into more effective and better performance format and structure."
- **Git labor split, agent side:** everything git-adjacent beyond the user-run mutations is the agent's work — "I only review and you do the work for me." No attribution lines on commits. Never revert the user's hand edits via git checkout.
- **GitHub = human review gate:** "I actually don't do automated GitHub work by AI directly, I usually review what you generated before doing in GitHub... in GitHub, it is much more strict on the standard."
- **Student, multi-domain; CLAUDE.md stays universal:** "As I am a student, I do many things, mostly AI work... I don't want the CLAUDE.md to be too limited to a specific structure of work, they should be high level instructions." Per-type layering lives in project CLAUDE.md and project rules.
- **OSS artifact publication:** design/plan/ADR docs push to the same GitHub repo, open and closed source alike; push counts as publishing, checked inside the existing review pass. Per-document exceptions only: commercial strategy, operational security detail, PII/secrets, legal.
- **Reject-on-comment:** a tool call the user rejects with a comment is a silent rejection — track landed versus rejected, and re-apply only after addressing the comment ("I think I rejected the edit due to the comment, as Claude Code reject tools when commenting.").

## 3. Working principles

Bar: named methods and stances governing how harness work is judged, each with its why; nothing a SOTA model infers unprompted.

- **Work-sequence principle "3M":** Make it work / Make it right / Make it fast — the user's own sequencing lineage, kin to the Rule of Three ("So the Rule of Three is similar to my previous principle of 3M?").
- **Firing guarantees over conditional token savings:** a standing rule's reliable firing outweighs relocating it out of always-loaded context — "the reason that I don't put them into skill is that I afraid of forgetting to use them."
- **Context dilution and re-trim:** bloated context dilutes attention; an 80%+ system-prompt cut showed no eval drop ("We should trim our context for more intelligent models"). Verification and self-correction belong in the architecture, not the prompt. Re-trim standing context per model release — each release widens what the model infers unprompted; the user's judgment is the gatekeeper meta-layer.
- **Admission test for standing context:** always-loaded material is for what is true for every prompt — context is a standing cost paid on every request, guilty until proven useful. Delete in blocks, not lines: sentence-level cuts sit inside eval noise. Failure taxonomy (Breunig): poisoning / distraction / confusion / clash, clash being the self-authored contradiction class. Rules land as judgment ("X is usually right here because <reason>"), never bare.
- **Unknowns bottleneck:** work quality is bottlenecked by clarifying unknowns, not model capability — blind-spot pass, throwaway prototypes, one-question-at-a-time interviews, code references over screenshots, implementation-notes log, pre-merge quiz.
- **Ralph-wiggum-loop:** early completion plus a soft gate ships half-done work; the fix is an objective gate — "not a verifier that has an opinion".
- **Comprehension-debt:** output outpaces understanding; review scale must track automation scale — "gates rot".
- **Deep over shallow (深模組/淺模組):** AI leans shallow — easy to build, hard to manage, lost on large projects; prefer deep modules (narrow interface, rich implementation). 規格化/流程化/模組化 — spec-ify, process-ify, modularize — are what make AI vibe coding more than a toy.
- **Multi-agent decomposition and verification:** decompose by context boundary, never by role (role splits spend more on coordination than work); multi-agent remedies exactly three constraints — context protection, parallelization, specialization past ~20 tools — at a typical 3-10x token cost. Pool independent judgments, never debate: debate induces premature consensus, and centralized verification cuts error amplification (17.2x → 4.4x). Unfiltered review runs 12-15% precision; the verify-to-disprove stage is what reaches <1% — never ask "what's missing" freeform, LLM judges are weakest at exactly that (FineSurE's said-but-not-written alignment is the published method). Production pattern: parallel specialized finders → disproof verifier → severity ranking → the human keeps the verdict. Mechanical gates — proof-of-concept execution, non-zero exit — are what make parallel fan-out trustworthy; a graph view exists because parallel work is otherwise unobservable. The verification pass's named failure is early victory; the fix is an explicit complete-suite demand.
- **Anchor edits insert, never replace:** the anchor text stays verbatim in both old_string and new_string; new content goes beside it, never over it ("Why are you keep removing unrelated part when you edit?" — three corrections).
- **Plan-acceptance gate:** before asking the user to accept a plan, state the method — what was dispatched, what was read, which layers are covered — and expect a fact-check demand next.
- **Doc-sync standing instruction:** durable docs carry the latest and most accurate context, no ambiguity ("All docs should be containing the latest and most accurate context. Try your best to avoid any ambiguity and unclear context."); sweep for staleness before every compact.
- **Imperative verbs stay:** instruction bullets keep their imperative verbs — stripping them softens the rule ("Just asking, why remove the verb?").
- **Justify-before-execute:** on a heavy plan, justify per item that it is worth doing before executing anything.
- **Standard over house:** reason from the standard or best practice, neither from the user's CLAUDE.md preferences nor by citing a named standard ("Don't lean to my CLAUDE.md preference... You should reason about how would the docs format." / "use the standard/best practice in formatting.").
- **Gate status is the user's word:** never mark a gate, batch, or review done without the user's explicit confirmation; status lines stay "in user review" until then; the agent's expectation of completion is not completion.
- **Inference-bar re-test:** every always-loaded instruction is re-tested against the inference bar (a SOTA model does it unprompted, even under time pressure) whenever standing context is restructured; relocation fixes home-correctness, never permanence, and what survives lives exactly once.
- **Two-layer resolution for rules/skill overlap:** resolve by layer, never by deletion — rules keep the policy and the attention checklists that must fire on edit; skills own the depth invoked on demand. A rules-file reference to skills names the complete relevant family, never a partial set.
- **Three-way restructure method:** for a contested rewrite, draft in parallel (main context + fresh subagent), apply the mechanically identical overlap first (script-verified), then walk every divergence one-by-one for user verdicts — the divergence review is where the value lands.
- **Live-test protocol:** when a reworked surface goes into real-session use, commit mid-arc and let the user's hand edits land on top; the next session reads the diff, judges every change against the harness principles, and reverts only the bad ones with reasons — the user's reasons win conflicts.
- **No agent time estimates:** wall-clock inputs are invisible to the agent (review speed, permission prompts, machine latency, subagent runtimes), so any time estimate is a fabricated number; false precision harms planning more than no estimate.
- **Restoring a deleted rule needs live evidence:** "the problem no longer occurs" is contaminated evidence while the rule is still active during the observation window; the valid grounds are severity, form (a pure negative constraint is the weakest), and whether a safety net exists.

## 4. Component standards

Bar: decisions and whys for authoring and curating skills, commands, agents, rules; live rule text lives in harness-maintenance and rules, pointed at, never copied.

- **Generic args, never hardcoded names:** commands and templates take generic argument names — never hardcode a project's folder or file names ("Don't specifically call 'system_design/' or something else... I may use other").
- **Universal principles migrate to the trunk; rules keep mechanics:** a principle in a rules file that applies to every prompt moves to CLAUDE.md; the rules file keeps the mechanics and the checklists that fire on its scoped reads.
- **The 200-line bar calibrates, never caps:** instruction files target under 200 lines (Anthropic's recommendation) as a membership test, not a numeric cap: procedures belong to rules and skills, every-session facts to the trunk; a project instruction file earns entries by purpose and gotchas, never content learnable by listing directories.
- **External corpora are content donors, never authorities:** clone-and-mine a source for adoptable content on merit; never reconcile the harness tree against the source's state — its goals are not this harness's, and authority status imports its drift.
- **Coding and language-specific detail lives in scoped rules, never the trunk:** CLAUDE.md stays at principles, preferences, and instructions; per-language toolchains, style, verification pipelines, and naming detail default to the language's rules file, where scoped loading puts them in view exactly when that language is edited.
- **Transparency principle:** a component with no readable body (a hidden built-in) may never be referenced from a durable file — the reader cannot verify what the reference promises, and the reference rots invisibly with the component.
- **Routing lives in descriptions; only conversational openings are fixed:** a phase-membership table in always-loaded context is removed form — it pays for what the injected descriptions already carry, and an overflowing phase is a curation signal, not a layout problem.
- **House skill style (mattpocock lineage):** terse, accurate terms, free phase transitions; one skill = one specific purpose; other sources complement, never set the bar. Drops are usage-based only and never silent — every drop records its reason.

## 5. Workflow decisions

Bar: rulings that shaped the artifact and workflow system with their why; mechanics live in the workflow skills.

- **Doc-separation adoption:** project knowledge separates into AGENTS.md (rules/process), CONTEXT.md (glossary/ubiquitous language), ADR (one decision per file) — the frame behind this harness's CONTEXT.md and OPEN-QUESTIONS.md adoption.
- **Feature, component, INDEX:** a feature is a group of components built together, sized so the brief fits one fresh context (no number band: "what if it is actually better to have 7 components?"); bigger features split along dependency seams. A component is the smallest independent buildable unit; INDEX is the cross-feature menu with dependency ordering. Never "batch" or "menu"; "epic" rejected as too large. The terms are the workflow skills' own vocabulary.

- **Three-layer rtk permissions (settings.json, rebuilt 2026-10-27, probe-verified):** every allow entry is three layers — plain (rewrite-miss insurance), rtk middle (the engine's verified output target), proxy (the deliberate raw-output escape). The rtk PreToolUse hook rewrites via updatedInput BEFORE permission evaluation, so rules match the rewritten string; rtk proxy is raw-with-tracking, rtk run (raw, untracked) is denied. Ask carries only universal dangerous verbs (rm, curl, wget, winget); stack-specific installs prompt via default mode — the settings file does not enumerate the toolchain. Write paths inside allows are mechanically excluded (tsc scoped to --noEmit, lint exact-matched so --fix falls through, ruff/mypy/playwright removed). Probe method: settings load at session start (restart to apply); the user observes prompts (the agent cannot) — allow probes run silent, ask probes are rejected by the user, deny probes auto-fail.
- **Claude Code permission mechanics (docs + live verified):** deny > ask > allow, first match regardless of specificity — a catch-all ask defeats every specific allow (the rtk proxy catch-all was removed for exactly this; defaultMode=default with bypass disabled makes unlisted commands prompt anyway). Space-star (X *) is the canonical wildcard and also matches the bare command; X* over-matches (ls* catches lsof); an exact entry matches only the exact string. Compound commands evaluate per subcommand with ask/deny contagious across subshells. Redirect targets are checked against Edit/Write rules separately — a Bash allow never approves the target, so read-only allows cannot be hijacked into writes (/dev/null exempt). Read/Edit deny rules extend to Bash file commands (cat/head/tail/tee) and redirect targets; find-with-action flags (-exec/-delete) are never auto-approvable by prefix rules, and write-flag commands with unquoted globs prompt.
