# Canon

The consolidated decisions file for this harness — durable facts and rulings with their why. It is a state doc: the text states what IS; chronicle and superseded forms live in git history. The user's verbatim words are kept where the wording itself carries the rule, typos preserved.

---

## 1. Environment + loading model

Bar: machine- and account-level facts a session cannot infer and cannot change (provider setup, injection and loading mechanics, measured costs, environment failure modes).

- **settings.json waiver:** only genuinely new settings may be proposed. A staged settings.json token rides every clone and any future visibility change.
- **Built-in feature-disable layer:** bundled skills stay fully disabled; /doctor stays (user-typable diagnostics, model-hidden); a same-name project skill replaces a bundled one in the injection; bundled claude-api stays dead while the configured provider cannot serve it (re-evaluate on provider change). Permission denies block calls only — they never remove tools from the injected context, so deny lists save no tokens.
- **Security-plugin layer:** the injected at-write-time pattern warnings are the harness's only deterministic write-time net and stay on; the plugin's two LLM review layers stay off — the Stop-hook diff review hijacks the turn boundary on findings, and commit-time review is permanently dead here because the user runs every commit (if commit-time security review is ever wanted, the route is the Review phase's security-auditor under the user's gate, never the plugin's layers). The shared master switch for the two LLM layers is ENABLE_CODE_SECURITY_REVIEW in settings env; the un-gated per-prompt baseline capture (subprocess latency, zero tokens) is the accepted residual cost of keeping the pattern layer.
- **Output-cap mechanics:** unrecognized gateway model IDs default to a 32000-token output cap and thinking counts against it, so a long analysis turn dies before its first Write; the raise is CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000 in settings env (going higher rejected: the excess clamps to the provider ceiling and deepens the silent-generation window). Subagent cap deaths have no auto-resume on any version, and a resumed agent that emits nothing after the message lands does not recover — interrupt and dispatch fresh.
- **Task-tool denies are dead config:** the TaskCreate/TaskGet/TaskList/TaskUpdate denies in settings.json predate the tools' rename and match no live tool; the startup warnings on unregistered configs are the accepted price.
- **Plan mode is doctrinally off twice over:** it delegates exploration to a subagent, conflicting with the contents-vs-answer dispatch test, and the grill skills own the interrogation moment.
- **Token-defense taxonomy:** standing-context defenses class as [P] probe-proven, [V] version pins, [N] numbers, [C] protected checklists, [M] framework mechanics, [L] anchors, [R] routing, [U] presumed-only; the bulk of a rules layer is enforcement surface — a firing-guarantee decision, not an inferability question — and the class, never the token count, decides whether a defense holds.
- **Three-layer rtk permissions:** every allow entry is three layers — plain (rewrite-miss insurance), rtk middle (the engine's verified output target), proxy (the deliberate raw-output escape). The rtk PreToolUse hook rewrites via updatedInput before permission evaluation, so rules match the rewritten string; rtk proxy is raw-with-tracking and rtk run (raw, untracked) is denied. Ask carries only universal dangerous verbs (rm, curl, wget, winget); stack-specific installs prompt via default mode — the settings file does not enumerate the toolchain. Write paths inside allows are mechanically excluded. Probe method: settings load at session start (restart to apply); the user observes prompts (the agent cannot) — allow probes run silent, ask probes are rejected by the user, deny probes auto-fail.
- **Claude Code permission mechanics:** deny > ask > allow, first match regardless of specificity — a catch-all ask defeats every specific allow (defaultMode=default with bypass disabled makes unlisted commands prompt anyway). Space-star (X *) is the canonical wildcard and also matches the bare command; X* over-matches (ls* catches lsof); an exact entry matches only the exact string. Compound commands evaluate per subcommand with ask/deny contagious across subshells. Redirect targets are checked against Edit/Write rules separately — a Bash allow never approves the target, so read-only allows cannot be hijacked into writes (/dev/null exempt). Read/Edit deny rules extend to Bash file commands (cat/head/tail/tee) and redirect targets; find-with-action flags (-exec/-delete) are never auto-approvable by prefix rules, and write-flag commands with unquoted globs prompt.
- **rtk rewrite map:** reliably rewritten — ls, git status/log/diff/show, grep (incl. rg → rtk grep), diff, wc, cat/head/tail → rtk read, pytest (all three spellings), vitest, jest, tsc, npm run lint → rtk lint (a semantic swap: rtk's eslint wrapper, not the project script — the proxy form runs the real script), npm run test. Never rewritten (the plain layer is live) — uv run pytest, winget, git blame, git ls-files, npm test, head -n (long flag), tail -f/-c. `rtk hook check <cmd>` dry-runs the engine. CC-Switch rewrites settings.json one-entry-per-line (compact multi-entry layouts do not survive it).
- **settings.json edit protocol:** scripted JSON rewrites corrupted the file once (recovered from git); changes go through the Edit tool only. The provider token is removable on demand — the user strips it for full-file reads during permission work and re-adds after.

## 2. Working principles

Bar: named methods and stances governing how harness work is judged, each with its why; nothing a SOTA model infers unprompted.

- **Admission test for standing context:** context is a standing cost paid on every request, guilty until proven useful. Delete in blocks, not lines: sentence-level cuts sit inside eval noise. Rules land as judgment ("X is usually right here because <reason>"), never bare. Every always-loaded instruction is re-tested against the inference bar whenever standing context is restructured; relocation fixes home-correctness, never permanence, and what survives lives exactly once.
- **Imperative verbs stay:** instruction bullets keep their imperative verbs — stripping them softens the rule ("Just asking, why remove the verb?").
- **Live-test protocol:** when a reworked surface goes into real-session use, commit mid-arc and let the user's hand edits land on top; the next session reads the diff, judges every change against the harness principles, and reverts only the bad ones with reasons — the user's reasons win conflicts.
- **Restoring a deleted rule needs live evidence:** an observation that the problem no longer occurs is contaminated evidence while the rule is still active during the window; the valid grounds are severity, form (a pure negative constraint is the weakest), and whether a safety net exists.
- **CP principle (fresh-context economics):** each fresh context costs a full artifact read plus its own reasoning, and the marginal-return curve is steep — the first fresh reader is the no-self-acceptance core and irreplaceable; a second to fourth pays only when the briefs are structurally different (same-brief contexts converge instead of corroborating); more almost never pays; minor work never warrants a crowd. Generation moments are the exception and keep their fan-outs — divergence is the product there, and a fresh-context pass must not trim them as violations.
- **The whole-surface audit runs heterogeneous lanes and lands serially:** parallel findings-only subagents (one lens each, surface split by file class or component) report to main, which dedupes and falsifies the findings and lands the survivors one at a time; a fresh-context verifier confirms the landed bytes per dispatch-protocol's Batch final-audit.
- **Superset lenses and verdict contracts:** two review lenses seated on one checklist produce correlated agreement that reads as confirmation — every lens owns a distinct checklist; and a verdict contract carries an explicit not-applicable value, because a scope-guarded reviewer otherwise improvises a silent pass. A lens earns its own file only when a generic reviewer plus one line could not produce it (the justification test).
- **Audit flags are diagnosis, not verdict:** findings from a review or audit pass are leads to verify, never instructions to execute; a buried gotcha can be load-bearing, so triage findings by evidence, never by prominence. The verification step lives in dispatch-protocol's No self-verification.
- **Content-preservation scan on consolidation edits:** scan the deletion side of the diff (`git diff | grep '^-[^-]'`) for lost backticks and acronyms, and keep the per-file word-count delta non-negative — losses hide in deletions, invisible to a read of the result.
- **Rename-parks are live until the user rules:** a `.bak`-style rename parks a file, it is not a deletion signal — never clean up parked files without the user's word ("Don't delete it, I only renamed this, it is not a backup.").
- **Unclear instructions are a root cause, not an excuse:** when a standing instruction fails repeatedly, trade its breadth for unambiguity; contradictory guidance is an invisible tax (clash: the self-authored contradiction class).
- **Universality two-filter test:** an exception owned by a mode-skill (prototype skipping a production-weighted rule) does not count against a rule's universality, and conditional-within-default-mode content moves to the skill's home; the filter runs per work mode (production vs side-project/prototype), never by exception count.
- **Skill anchors are phase-anchored and earned:** a skill owning a mid-flow moment routes by a phase-anchored trunk mention plus its description (tdd: named at the trunk's build step, triggered by its description), never by wiring invocations into upstream skills; the anchor is earned only when the moment is a mid-phase instant the model will not think to invoke on its own; phase-explicit spine steps self-defend through their pipeline position (tdd anchors for most builds, code-review sometimes). Routing is verified at the phase moment itself (the skill is never step one), and never judged from a probe run with --tools "" — that flag strips Skill-tool planning, an environment flaw, not a routing failure.
- **Design-time guidance has exactly two homes:** skills or the trunk; paths:-scoped rules can never serve design time because design moments have no matching working file (grilling has no cwd).
- **Relocation math:** moving always-loaded words into a new skill's description saves nothing — the description is itself always-loaded and a thin skill is only a routing shell; relocation pays only when the receiving component already exists, and a rule the baseline probe shows firing (banned patterns hit at code-time) compresses in place instead of moving.
- **Indirect probes beat direct questioning:** to test whether a rule fires, seed a task simulation with non-canonical vocabulary and watch the behavior; asking "did rule X apply?" invites confabulated agreement.
- **Behavior-affecting trims get before/after probes:** a trim whose loss could change task behavior is verified by running the same task headlessly before and after it, never judged from the diff alone — a static read cannot see a firing rule go silent.
- **Baseline-probe method:** a no-file-read probe is a natural no-rules baseline; unprompted-produced means inferable means deletable, missed means teeth means keep — "settle it by running the document, not by debate". Probe silence never proves capability (pins stay). Mechanism-class hits transfer across SOTA models while taste-class results vary within one, so a defense names its class; under the always-loaded confound (prior vs trunk coverage both zeroing a rules file's marginal value) a defense must say which. Probe reading is item-precise, generation moment and review moment are distinct, probe questions and outputs transfer to subagents verbatim, and adversarial re-checks open a NEW context (resuming the trim auditor to defend grades its own work). The structure is trim auditor × fresh defender × probes, with a pre-commit dual-resume carrying the rejected-class checklist.
- **Globs declare the need-moment:** a scoped rule's glob states when the rule is needed, derived from the actual use case; token savings are a by-product, never the motive.
- **Landmark principle:** a heading that is an audit's only scan landmark for a skill route, mechanism string, or named convention may not be demoted even when its text survives in the body; a cross-file merge is a glob-scope change, not a structure change.
- **Trim accounting reports against the promise:** a promised savings range is a commitment — delivered deltas are reported against it with misses on record, never silently re-baselined.
- **Preference-carrying context beats fresh subagents on trim proposals:** the session holding the user's demonstrated preferences finds more trimmable material than a fresh reader; freshness serves verification and defense, never preference work.
- **Keep/drop judges purpose and workflow fit, never invocation count or provenance:** usage frequency is supporting evidence, never the criterion, and provenance never enters the call.
- **Textbook-example trim bar:** a textbook-level example whose prose already carries the rule is deletable; a structure-carrying example (its shape is the lesson) is protected.
- **Descriptions do not prove coverage:** before cutting content on skill-coverage grounds, read the skill body itself — a description can appear to carry a rule the body lacks.
- **Floor lists close trim and audit reports:** the report ends with the items judged untrimmable, each with a one-line reason, preventing re-proposal in later rounds — the report-level kin of the rejection register.
- **Wrapper-filtered output is not evidence until blob-verified:** condensed diff rendering mangles markers against markdown list dashes and grep hit-lists get polluted by code-fence comments — verify a load-bearing hunk at the blob (`git show <rev>:<file>`) before writing a finding; identity claims need the raw path (`rtk proxy diff`) or a checksum.
- **Doc-craft judgment tools:** a local intro does not re-gloss what its own sub-sections define; static verbs reject frequency adverbials ("carries X into every session"); candidate lists are not durable content — choices and preferences are; a guaranteed co-load (globs) makes a pointer between the files a no-op.
- **Review rubrics for instruction text:** behavior-extending rationales teach the danger class so unlisted forms stay judgeable — keep; state explanations that add no behavior — drop. A condition-anchored rule must make the condition do work; the unconditional form is usually shorter and stronger. Rules text says "the user"; the user-voice section is deliberate. Only capability-premised trims are probeable; adjudication-based drops need no probe. When every list item is an instance of an adjacent class rule, delete the list and relabel the class rule as the primary grant. A scope-possessive ("the project's") denotes the scope's full instruction set — naming one file under-claims. A colon follows an independent clause, never a fragment label.
- **Rule-criticality five-type lens:** good non-default (keep); good but model-default (trim); worse than default (drop); preference pins (judged on consistency, not truth); mechanically-checkable (prose carries only the config directive). Tier A toolchain pins were verified against the industry field — each challenger (ty, Pyrefly, Biome, tsgo) wins one axis, none the standard.
- **Claim classes expire differently:** capability claims (what models do unprompted) expire with model generations and need fresh probes; loader and architecture facts stand until the version changes; adjudicated user preferences never expire on capability grounds and reopen only by the user.
- **Probe instruments:** fresh `claude -p` processes only — subagent contexts inherit the session-start snapshot, so mid-session edits never propagate into a probe; delete first, probe after; PASS/FAIL pre-registered before the run; a control is mandatory; grade in main context, never by the subject; empty stdout with exit 0 is INVALID, re-run once; every claim carries its n=1 caveat; prompts in English (the drift condition is Chinese-reply pressure on the artifact, never a Chinese prompt); probes test removal drift, never an addition's value; security-critical passes don't trim on n=1. Instruments: stream-json --verbose captures events (the session-JSONL grading path holds no probe transcripts); invocations verify by grepping the session JSONL for the skill name; a prompt referencing an absent file gets refused under --tools ""; the secret-path hook can match the prompt's own wording.
- **Follow-ups resume the same agent:** a re-audit or follow-up sweep over material an agent already read resumes that agent rather than dispatching fresh — the accumulated read is the asset; the fresh-context lever governs failed retries, never succeeded follow-ups.
- **A title can seat a stance:** grading coverage reads titles, not just bodies — a titled section counts as stance coverage even when its body is pure mechanics (the vocabulary-vs-stance base rule lives in harness-maintenance's layer check).
- **Reinforcement across consumption moments is not duplication:** the same rule recurring where each consumption moment needs it is reinforcement; mention-once (the trunk's rule) governs only within a single consumption moment.
- **Glob-deserve test for merges:** every absorbed member must deserve the shared glob, not merely happen to share it. Accepted approximation costs stand (use-* basename false positives, app/ and pages/ over-fire on Angular-style trees, middleware.ts matching non-Next files, web/testing missing Playwright's tests/ default, fastapi.md path globs false-positiving on same-named dirs, no vue/svelte/astro glob — the harness is tuned to the user's React stack): each fix's over-fire risk exceeds its gap's cost.
- **Extraction's two directions:** a narrowing block must be glob-addressable (LLM integration, the RSC boundary, env exposure, and security response protocol fail it); widening is legal but taxed; suspected-default content never widens (compounds the error).
- **Process lessons:** Verify a mechanism exists before explaining or relying on it — check the schema first. Never declare "no savings": partial reductions accumulate, and file-level dissolution is judged with net-token math plus per-item deletion tests. A fix proposal must pass the target file's own rules too — a fix copied from an audit report once introduced the very defect the batch was eliminating. `git diff --stat` against the planned per-file deltas is the fast acceptance check for a deletion batch. A probe procedure must exercise the rule's trigger shape. Merge sweeps grep the whole harness, not one tree. A compression that adds a clause can create a two-home duplicate — grep for the clause's existing home before keeping it. Testimony is not evidence: records say where to look, and only live observation says what is true. A declared ordering is not an execution order — instructions tied to a future event fire at the event. `claude -p` mechanics: prompt first, flags after (a leading `--tools ""` swallows the prompt); behavior probes return the artifact in stdout (in -p mode a Write can be permission-denied with no approver); on the user's proxy a haiku alias routes to a different provider model and the unrecognized-model line is noise. Filtered transcript extraction can miss visible messages — name the miss class in the not-covered note.
- **Upstream-review method (adoption falsification):** per hunk — premise-fit (no conflict with the target's own premise or red lines), purpose-translation (the discipline serves the same purpose in the new seat), real-need (the need-moment exists in this harness's workflows), inferable-remainder (non-inferable behavior survives mapping against seated content); re-check rejections too — a component-level verdict says nothing about its content, and purpose overlap tests partially. Standing guardrails: local descriptions are adjudicated routing surfaces — compare bodies, never re-import an upstream description wholesale; reopen a description only when a body change alters scope, trigger, invocation mode, or the returned contract; deploy-watch stays unadopted; wizard and teach-back stay user-invoked; inherit-legacy-style keeps its existing-codebase framing; provenance corrections need historical evidence plus a current-source comparison.
- **Open-sample vs closed-enumeration test:** an open sample list under a named general class needs no per-section maintenance; a closed enumeration with no general class named misroutes on unlisted moments — the test is whether the current text causes a wrong routing decision.

## 3. Component standards

Bar: decisions and whys for authoring and curating skills, commands, agents, rules; live rule text lives in harness-maintenance and rules, pointed at, never copied.

- **Transparency principle:** a component with no readable body (a hidden built-in) may never be referenced from a durable file — the reader cannot verify what the reference promises, and the reference rots invisibly with the component.
- **Locality: no caller-specific exceptions in general-purpose skills:** a skill serving many callers never carries one caller's exception; the invoking skill owns its own steps' staffing.
- **Owned components are tailored descendants, not copies:** a drift comparison hunts content deltas only — style deltas are the tailoring itself, never a defect; no blind re-syncing.
- **Description protected classes:** the corpus at floor keeps description content in five protected classes — symptom and match words, mis-invocation guards, genuine-overlap cede clauses, deliverable definitions, dispatch-mode clauses; a trim cuts outside these, never inside.
- **Description-walk bar and precedents:** the bar — terse unless genuinely needed or sibling overlap exists; the review unit is the skill's own body plus its callees' bodies (callees' callees wait for their own turn). Precedents: a negation guard whose positive trigger already scopes is deletable; a cede clause whose boundary the sibling's body enforces is a second home — cut; under-claims are description bugs too; the user-invoked bar in practice is stance-only, enumeration allowed for /-menu picking; third-person "the user" is the trigger convention, and person never depends on invocation mode — a "you" safe in /-menu text becomes the agent-runs-commands misreading after a mode flip; invocation mode is multi-axis (frequency, flow weight and risk, discovery value, adequacy of the no-skill fallback); descriptions open with an imperative or a noun phrase, first-verb -s normalizes; scope statements use "existing", with "legacy" only as a subset trigger match word; no synonym rotation between description and body — named theory stays named; after the clause audit, re-check for a concept written twice and compress second mentions. Forgetting-fear asymmetry: high-frequency skills suit user-invoked; low-frequency skills need the listing as their discovery mechanism.

## 4. Rejection register

Bar: one consolidated register of rejections-with-why (anti-re-proposal value only).

- **Skill-folder categories** (nested directories under skills/): rejected — the loader does not discover nested directories; the tree stays flat.
- **Wholesale harness rebuild:** rejected — "'whole restructure' and 'add every tool' are the same instinct in a new costume"; an audit comment mandates improvement, never wholesale rewrite.
- **Project-memory deletion:** rejected — "scar tissue, not direction... deleting guarantees recurrence"; deletions that correct wrongness or land-then-prune stay legitimate.
- **claude-md-management: KEEP** — owns project-side CLAUDE.md audit; the only plugin-sourced skill with an unowned moment.
- **Design-cluster pipeline doctrine:** whole-inventory dedup against the same-moment lens returns zero drops — the design cluster is a pipeline, one skill per gate; the closest pair (prototype's UI branch × design-variants) is two media, not one; the design-taste-frontend × redesign-existing-projects overlap resolved the same way (the existing-site audit stays as design-taste's payload, with redesign-protocol.md carrying mode and preservation calls). Do not re-propose merging the cluster.
- **A done is a done:** completed arcs' scratch scaffolding (logs, handoffs, source clones) is not kept past its fold — the harness files keep evolving and recovery is git history plus transcripts.
- **Disabled plugins are deliberate keeps:** disabled is a parking state for future need, not residue — removal needs a real obsolescence case, never staleness alone.
- **redesign-existing-projects stays separate from design-taste-frontend:** upgrade-in-place vs new-UI-from-brief are distinct usages, and the creation-vs-preservation stance split is what routing depends on (same shape as document-generate × document-release); upstream keeps them separate; zero checklist duplication. Do not re-propose the merge.
- **Three thinner-but-tolerable boundaries, reviewed and kept:** make-interfaces-feel-better × design-taste-frontend, agent-architecture-audit × agent-introspection-debugging, research × search-first; each overlap was reviewed and judged tolerable. Do not re-propose merging them.
- **database-reviewer fleet slot in code-review, withdrawn by falsification:** the agent's description trigger and database-migrations' ship-moment dispatch already route the specialist; a fleet slot pays the four-surface taxonomy cost for a rare seam.
- **Vetoed removals, all held:** the 800-line ceiling stays single-homed in review-standards; agent-introspection-debugging's three generic debug rows stay (the removal criterion was over-broad); session-sync's and bake-design's Commit steps stay under the neutral-git ruling; react's hooks derive-state row stays (a useEffect-misuse entry, not a restatement).
- **Lean-core re-architecture advice, rejected:** the recommended split (a minimal always-loaded core plus load-on-demand everything) already exists where it pays (coding rules are paths:-scoped) and is deliberately refused where it would cost: the advice's own mid-tier failure list (skill-skipping, style drift on durable artifacts, subagent-contract violation) enumerates exactly what the unscoped dispatch contract prevents. Its sizing is likewise generic-fleet advice, priced for mid-tier daily drivers and never calibrated to this fleet, whose top tier runs the full set daily without degradation.
- **Inventory count-trim, zero survivors:** every suspect pair survived falsification with independent purpose (document-generate × document-release are create-vs-update triggers; qa × e2e-testing are exploratory-vs-suite; teach × teach-back are user-locked), and the longest descriptions earned their length (cede clauses and guards block real mis-invocations; weaker tiers lean on trigger words). Do not re-propose count trims.
- **Inventory drop floor, no survivor:** no skill passes the drop no-op test — each carries user-workflow conventions, non-inferable teeth, or specific deliverable specs; user-invoked skills sit outside injection-cost arguments (absent from the always-on listing). Do not re-propose skill drops.
- **Grill pair merge (grill-me × grill-with-docs), rejected:** the fixed openings are the harness's highest-traffic routing rule, and two names keep the routing zero-judgment (the doc-context branch is carried by the invocation itself, never judged in-session); the second name's cost is the accepted price.
- **Review-agent inlining, rejected:** the review agents' tool gating is load-bearing, so inlining their review into the invoking skill or a merged agent drops the curated-tool backstop the dispatch relies on.
- **Form-is-function protection for scan lists:** restructuring a protected list for form was withdrawn — "形式不是鷹架，形式就是功能" (form is not scaffolding; form is the function): a short scan list's shape carries its use, and reshaping it is a fidelity defect, not a cleanup.
- **Security coverage extends existing components, no new skill:** a pre-launch security skill was rejected ("I don't want a new skills... no new files"); the launch gate rides land-and-deploy's security-surface trigger. AI-IP posture (AI-code copyright, GPL contamination) is adjudicated accept-risk — an awareness item with no enforceable mechanism, reopened only by a material change in law or platform policy.
- **Role-term rejections:** vibe coding, vibe engineering, and agentic engineering all rejected on register and definition mismatch — the plain sentence is the precision floor; CLAUDE.md's Design header bundles settle and architecture deliberately (the industry's Specify/Design split lives in the spine).
- **Glob-scope reshaping proposals, rejected:** stripping .tsx/.jsx from web/ globs (collides with need-moment globs and firing guarantees); splitting common/ into core plus conditional layers (collides with the firing-guarantee ruling, and the task-concern split already is the status quo); moving React content into typescript/* (factually false — none exists there). The measured basis: a plain .tsx read injects 16 rule files, not the claimed 18.
- **Upstream-review standing rulings:** deliberate multi-seat duplications stand — the craft-floor reflexes sit in three seats (design-build's Verify floor, make-interfaces-feel-better's principle, plan-review's design lens), and the measure ranges are an adjudicated divergence, not a conflict (design-build's 65-75ch build-time floor vs make-interfaces-feel-better's 45-75ch polish-time band; the seats' own scopes tie-break). README's Compound section stays dissolved (components sit under their original repo rows with merge notes). Do not re-propose re-merging.
- **reverse-skill router merge, rejected at N=2:** full-pack and master-router extraction rejected at adoption; api-security and llm-security landed single-file carrying the scope-gate line (a user naming a target is not by itself authorization — the skills' bodies are its home); a merged router skill was rejected at N=2 (diluted routing surface; read-the-router-skip-the-playbook), reopening only if a third module ever earns extraction. Do not re-propose the merge.
- **Main-agent persisting subagent reports, rejected:** subagents write their own reports to disk (the dispatch protocol's report contract); main-agent persist was rejected — main-context tax plus transcription drift.

## 5. Open items

Bar: work the user has not settled; each names its owner and next concrete step.

- **Standing caveats on rewrite verification:** four limits, each open until its detector exists: (1) no metrics prove a rewrite improves model behavior (the less-direction philosophy rests on Anthropic's evidence, not local measurement); (2) real auto-invocation behavior is unverifiable headlessly (probes are false-negative-prone), so description quality is judged statically; (3) scoped-rules compaction survival is unobserved, watched only at natural compactions; (4) cross-session drift is invisible from inside one session; a whole-inventory audit is the only detector. Owner: the user; reopen triggers: a local eval harness, a working headless routing probe, an observed compaction, the next whole-inventory audit.

## 6. Source map

Bar: surviving primary sources and how to read them.

- **Transcript reading method:** never raw-load a session transcript; python-extract a line map first, then targeted reads of the mapped ranges. Transcript timestamps are UTC while local records run UTC+8; a same-evening UTC event carries the next day's local date.
