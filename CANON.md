# Harness Canon

The durable rulings of this harness with their why, and the live rulebook for its maintenance; [harness-maintenance.md](.claude/rules/harness-maintenance.md) holds the edit gates and the map that loads this file.

## 1. Authoring skills, commands, and agents

- **Multi-exemplar:** read sibling components before writing; base format and structure on the best practice across them, never on one target.
- **Persona and headings:** agents get a terse persona (1–3 sentences covering role, specialty, responsibility) at the top of the body, and no H1. Commands and skills get no persona; an H1 only when a genuine title beyond the bare name.
- **Frontmatter:** `name`, `description`, then `disable-model-invocation` and `argument-hint` when present, `tools` (agent allowlist; omit for all; the gating is load-bearing — a read-only agent carries read-only tools), `origin`; add `part-of` when the component belongs to another. `origin` is `custom` (hand-built here), a source name (the plugin name for plugins, the repo name for repos), or `A + B` (multi-source merge). Quote `description` with `""` only when it contains a colon. `argument-hint` marks required slots with `<>`, optional with `[]`; a complete-sentence question hint stays unbracketed; quote it only when YAML requires (a leading `[` or an inner colon).
- **Invocation mode:** model-invoked is the default; interaction- and session-bound skills (need the user in the loop or the live context) are user-invoked, execution skills (mid-flow builds, gates) and dispatchable file-bound analysis (findings, reports) are model-invoked, fired by their triggers; the user's call settles per-component exceptions.
- **Description = the routing surface:** one to three sentences carrying stance, trigger, and the mis-invocation guard, with returns as a phrase at most; never a workflow summary; path specs and behavioral detail live in the body. The mis-invocation guard covers lexical or state ambiguity only; naming other skills or phases is workflow-layer routing. A ceding clause naming a sibling skill ("for X, use Y") is allowed only when the two triggers overlap on the same user phrasing even after both are made task-precise; it never summarizes the sibling. User-invoked components (`disable-model-invocation: true`) drop the trigger and the mis-invocation guard and keep a one-to-two-sentence statement of what it does. A `## When to invoke` body section is an anti-pattern; relocate its load-bearing content into the description — but only when the trigger fires at or before the content's need-moment; otherwise the content moves to the always-loaded surface beside the decision.
- **Description rulings:** a floor-terse description keeps content in five protected classes — symptom and match words, mis-invocation guards, genuine-overlap cede clauses, deliverable definitions, dispatch-mode clauses; a trim cuts outside these, never inside. Descriptions open with an imperative or a noun phrase; no synonym rotation between description and body — named theory stays named.
- **Skill references in bodies:** when the referenced skill's procedure executes inline in the current flow, the reference is an invocation, written `call the Skill tool with "X"` (a one-line gloss may follow the call, never replace it). At a genuine boundary (hand-off, user-choice option, ownership statement, ceding clause, vocabulary or file pointer) a plain mention suffices. When the invocation's executor is a subagent, it goes into the dispatch prompt as the subagent's own action.
- **Locality:** a skill serving many callers never carries one caller's exception; the invoking skill owns its own steps' staffing.
- **Component form:** default to a single SKILL.md; a companion file (references, templates) earns its place only when the content genuinely doesn't fit, and a script only when the work can't be carried by instructions alone. Audit/check components inline their full spec (never repoint, since the referenced file may be the audit target, and spec overlap with CLAUDE.md is deliberate, not drift).

## 2. Adopting and extracting components

- **Extraction pipeline:** read the source and justify what to take → extract verbatim → remove the source's bad parts → enhance what survives → adapt to this harness's conventions and workflows (leave self-run git/gh mutations as-is; component bodies state the action without naming who runs it, except approval gates, which name the user and stay verbatim; the [CLAUDE.md § Git](CLAUDE.md#git) rules and the PreToolUse hook decide the mechanism) → verify against the sources that nothing useful was lost → final acceptance audit (per [dispatch-protocol §3 No self-verification](skills/dispatch-protocol/SKILL.md#3-no-self-verification)). Extraction is not a rewrite; relocate useful content, never drop it silently.
- **Source vetting:** before extracting from a pack that ships scripts, MCP configs, or bootstrap logic, audit its executable surface for unexplained network egress, credential-path reads, and instructions hidden in comments or HTML. Reads can execute; git drivers and hooks fire on git operations inside an untrusted checkout, and interpreters import project modules from the cwd. Read packs with the file tools only; never run git or an interpreter inside a pack's checkout.
- **Upstream review (adoption falsification):** per hunk — premise-fit (no conflict with this harness's premises or red lines), purpose-translation (the discipline serves the same purpose in its new home), real-need (the need-moment exists in this harness's workflows), inferable-remainder (the non-inferable residue survives merging into existing content).

## 3. Rules files and the trunk

- **CLAUDE.md is the trunk:** it carries preferences and instructions for the user's work; harness rules live in this file, not the trunk. The rules file is an extension of CLAUDE.md; neither restates the other. Coding rules never reference CLAUDE.md (it is already in context whenever rules load).
- **Trunk voice:** the How-to-work-with-me section speaks as the user in the first person, with the agent as you; every other trunk section refers to the user in the third person. A pronoun leak in either direction reads as the wrong vantage.
- **Reinforcement across consumption moments is not duplication:** the same rule may appear in each consumption moment that needs it; mention-once (the trunk's rule) applies only within one.

## 4. Permissions and protection layers

- **Security-plugin layer:** the security-guidance plugin has three layers; the write-time pattern warnings stay on as the only deterministic net, and the two LLM review layers stay off via the shared master switch ENABLE_CODE_SECURITY_REVIEW in settings env (the Stop-hook diff review hijacks the turn boundary on findings; commit-time review never fires — the user runs every commit). The un-gated per-prompt baseline capture (subprocess latency, zero tokens) is the accepted residual cost of the pattern layer.
- **Claude Code permission mechanics:** deny > ask > allow, first match regardless of specificity — a catch-all ask defeats every specific allow. A deny blocks the call, not the tool — deny lists save no tokens. Space-star (X *) is the canonical wildcard and matches the bare command. Compound commands evaluate per subcommand with ask/deny contagious across subshells. Redirect targets are checked against Edit/Write rules separately, so read-only allows cannot be hijacked into writes (/dev/null exempt). Read/Edit deny rules extend to Bash file commands (cat/head/tail/tee); find-with-action flags (-exec/-delete) are never auto-approvable by prefix rules, and write-flag commands with unquoted globs prompt.
- **Three-layer rtk permissions:** every allow entry is three layers — plain (rewrite-miss insurance), rtk middle (the engine's verified output target), proxy (the deliberate raw-output escape). The rtk PreToolUse hook rewrites the command before permission evaluation, so rules match the rewritten string; rtk proxy is raw-with-tracking and rtk run (raw, untracked) is denied. Ask carries only universal dangerous verbs (rm, curl, wget, winget); stack-specific installs prompt via default mode.
- **rtk rewrite map:** `rtk hook check <cmd>` dry-runs the engine — the authoritative per-command lookup for what the hook rewrites. npm run lint → rtk lint is a semantic swap (rtk's eslint wrapper, not the project script — the proxy form runs the real script). CC-Switch rewrites settings.json one-entry-per-line (compact multi-entry layouts do not survive it).

## 5. Probing

- **Probe method:** fresh `claude -p` processes only. To test whether a rule fires, seed a task simulation with non-canonical vocabulary and judge from the behavior — self-reports confabulate. A behavior-affecting trim is verified by running the same task before and after it, never judged from the diff alone; probes test removal drift, never an addition's value; the control runs before the first edit, a context control any time before the prune. Prompts in English (the drift condition is Chinese-reply pressure); empty stdout with exit 0 is INVALID, re-run once.
- **Probe rubric:** rules entries class by probe outcome — above default (keep), at default (trim), below default (drop); the class boundary reads off the control's output, so a control is mandatory. Silence never proves capability — version pins stay. Preference pins judge on consistency, never truth. Grade in main context; every claim carries its n=1 caveat; security-critical passes don't trim on n=1.
- **Loading probes:** verify a rule actually loads after a scoping change. Two headless probes — a context check (`claude -p 'Is a rule titled "<TITLE>" in your context? yes/no' --tools ""`, unscoped answers yes) and a load check (rerun with tools enabled, reading a matching file first; scoped answers no before, yes after the read). Probe only novel syntax shapes (character classes, braces, negation, path patterns). A failed probe stops the batch — report before proceeding. Measure de-load in total prompt tokens (input + cache_read), never input alone — cache shifts the split across processes. A backgrounded redirect can lose stdout; the session transcript in `~/.claude/projects/` is the ground truth.
